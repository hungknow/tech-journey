1. JSON Extraction Operators

-> (integer) - Extract Array Element

Function Signature: - json -> integer → json - jsonb -> integer → jsonb

Description: Extracts the nth element of a JSON array. Array elements are indexed from zero, and negative integers count from the end.

Usage Examples: 

-- Extract the 3rd element (index 2)
'[{"a":"foo"},{"b":"bar"},{"c":"baz"}]'::json -> 2
-- Result: {"c":"baz"}

-- Extract the 3rd element from the end (index -3)
'[{"a":"foo"},{"b":"bar"},{"c":"baz"}]'::json -> -3
-- Result: {"a":"foo"}

Important Notes: - Returns NULL if the array element doesn't exist - Supports negative indexing from the end of the array - Array indexing starts at 0

-> (text) - Extract Object Field

Function Signature: - json -> text → json - jsonb -> text → jsonb

Description: Extracts a JSON object field with the given key.

Usage Examples: 

-- Extract field 'a' from JSON object
'{"a": {"b":"foo"}}'::json -> 'a'
-- Result: {"b":"foo"}

-- Extract nested field
'{"user": {"name": "John", "age": 30}}'::jsonb -> 'user'
-- Result: {"name": "John", "age": 30}

Important Notes: - Returns NULL if the key doesn't exist - Returns nested JSON structures as-is - Works with both json and jsonb types

->> (integer) - Extract Array Element as Text

Function Signature: - json ->> integer → text - jsonb ->> integer → text

Description: Extracts the nth element of a JSON array, returning it as text.

Usage Examples: 

-- Extract 3rd element as text
'[1,2,3]'::json ->> 2
-- Result: '3'

-- Extract string element as text
'["apple", "banana", "cherry"]'::json ->> 1
-- Result: 'banana'

Important Notes: - Always returns text type, even for numbers - Returns NULL if element doesn't exist - JSON quotes are removed from strings

->> (text) - Extract Object Field as Text

Function Signature: - json ->> text → text - jsonb ->> text → text

Description: Extracts a JSON object field with the given key, returning it as text.

Usage Examples: 

-- Extract field 'b' as text
'{"a":1,"b":2}'::json ->> 'b'
-- Result: '2'

-- Extract string field
'{"name": "Alice", "city": "Boston"}'::jsonb ->> 'name'
-- Result: 'Alice'

Important Notes: - Returns NULL if key doesn't exist - Useful when you need text values instead of JSON - Numbers are converted to text representation

#> - Extract at Path

Function Signature: - json #> text[] → json - jsonb #> text[] → jsonb

Description: Extracts a JSON sub-object at the specified path, where path elements can be either field keys or array indexes.

Usage Examples: 

-- Navigate through nested structure
'{"a": {"b": ["foo","bar"]}}'::json #> '{a,b,1}'
-- Result: "bar"

-- Extract nested object
'{"users": {"admin": {"name": "root"}}}'::jsonb #> '{users,admin}'
-- Result: {"name": "root"}

Important Notes: - Path elements are specified as a text array - Can navigate through nested structures - Returns NULL if path doesn't exist - More readable than chained -> operators

#>> - Extract at Path as Text

Function Signature: - json #>> text[] → text - jsonb #>> text[] → text

Description: Extracts a JSON sub-object at the specified path, returning it as text.

Usage Examples: 

-- Extract nested value as text
'{"a": {"b": ["foo","bar"]}}'::json #>> '{a,b,1}'
-- Result: bar

-- Extract number as text
'{"data": {"value": 42}}'::jsonb #>> '{data,value}'
-- Result: 42

Important Notes: - Returns text representation without JSON quotes for strings - Returns NULL if path doesn't exist - Useful for extracting scalar values

2. Additional jsonb Operators

@> - Containment Test

Function Signature: - jsonb @> jsonb → boolean

Description: Tests whether the first JSON value contains the second JSON value.

Usage Examples: 

-- Check if object contains another object
'{"a":1, "b":2}'::jsonb @> '{"b":2}'::jsonb
-- Result: t

-- Check array containment
'[1,2,3]'::jsonb @> '[2]'::jsonb
-- Result: t

-- Nested structure containment
'{"user": {"name": "John", "age": 30}}'::jsonb @> '{"user": {"name": "John"}}'::jsonb
-- Result: t

Important Notes: - Supports indexing for efficient queries - Works with nested structures - Follows JSON containment semantics - Order doesn't matter for object keys or array elements

<@ - Containment Test (Reverse)

Function Signature: - jsonb <@ jsonb → boolean

Description: Tests whether the first JSON value is contained within the second JSON value.

Usage Examples: 

-- Check if object is contained in another
'{"b":2}'::jsonb <@ '{"a":1, "b":2}'::jsonb
-- Result: t

-- Check if subset of array
'[1,2]'::jsonb <@ '[1,2,3,4]'::jsonb
-- Result: t

Important Notes: - Reverse of @> operator - Useful for checking if a value is a subset of another - Supports indexing

? - Key/Element Existence

Function Signature: - jsonb ? text → boolean

Description: Tests whether a text string exists as a top-level key or array element within the JSON value.

Usage Examples: 

-- Check if key exists in object
'{"a":1, "b":2}'::jsonb ? 'b'
-- Result: t

-- Check if element exists in array
'["a", "b", "c"]'::jsonb ? 'b'
-- Result: t

-- Check non-existent key
'{"x": 1}'::jsonb ? 'y'
-- Result: f

Important Notes: - Only checks top-level keys and array elements - Can be used with indexes - Returns false for nested structures - Case-sensitive for keys

?| - Any Key/Element Exists

Function Signature: - jsonb ?| text[] → boolean

Description: Tests whether any of the strings in the text array exist as top-level keys or array elements.

Usage Examples: 

-- Check if any key exists
'{"a":1, "b":2, "c":3}'::jsonb ?| array['b', 'd']
-- Result: t

-- Check if any array element exists
'["apple", "banana", "cherry"]'::jsonb ?| array['grape', 'banana']
-- Result: t

Important Notes: - Returns true if at least one key/element exists - Can be used with indexes - Efficient for checking multiple keys

?& - All Keys/Elements Exist

Function Signature: - jsonb ?& text[] → boolean

Description: Tests whether all of the strings in the text array exist as top-level keys or array elements.

Usage Examples: 

-- Check if all keys exist
'["a", "b", "c"]'::jsonb ?& array['a', 'b']
-- Result: t

-- Check fails if any key is missing
'{"a":1, "b":2}'::jsonb ?& array['a', 'b', 'c']
-- Result: f

Important Notes: - Returns true only if all keys/elements exist - Can be used with indexes - Returns false if any key/element is missing

|| - Concatenation

Function Signature: - jsonb || jsonb → jsonb

Description: Concatenates two jsonb values. For arrays, concatenates all elements. For objects, creates union of keys with second object's values for duplicates. Other cases convert non-array input to single-element array.

Usage Examples: 

-- Concatenate arrays
'["a", "b"]'::jsonb || '["a", "d"]'::jsonb
-- Result: ["a", "b", "a", "d"]

-- Merge objects
'{"a": "b"}'::jsonb || '{"c": "d"}'::jsonb
-- Result: {"a": "b", "c": "d"}

-- Array + scalar
'[1, 2]'::jsonb || '3'::jsonb
-- Result: [1, 2, 3]

-- Object + scalar
'{"a": "b"}'::jsonb || '42'::jsonb
-- Result: [{"a": "b"}, 42]

-- Append array as single entry
'[1, 2]'::jsonb || jsonb_build_array('[3, 4]'::jsonb)
-- Result: [1, 2, [3, 4]]

Important Notes: - Does not operate recursively - For arrays, concatenates all elements - For objects, second object's values override duplicates - To append array as single entry, wrap in jsonb_build_array()

- (text) - Delete Key/Value

Function Signature: - jsonb - text → jsonb

Description: Deletes a key (and its value) from a JSON object, or matching string value(s) from a JSON array.

Usage Examples: 

-- Delete key from object
'{"a": "b", "c": "d"}'::jsonb - 'a'
-- Result: {"c": "d"}

-- Delete matching values from array
'["a", "b", "c", "b"]'::jsonb - 'b'
-- Result: ["a", "c"]

-- Delete non-existent key
'{"x": 1}'::jsonb - 'y'
-- Result: {"x": 1}

Important Notes: - Removes all matching values from arrays - Removes key and value from objects - Returns original structure if no match found - Only removes top-level keys

- (text[]) - Delete Multiple Keys

Function Signature: - jsonb - text[] → jsonb

Description: Deletes all matching keys or array elements from the left operand.

Usage Examples: 

-- Delete multiple keys at once
'{"a": "b", "c": "d"}'::jsonb - '{a,c}'::text[]
-- Result: {}

-- Delete multiple array elements
'["a", "b", "c", "d"]'::jsonb - '{b,d}'::text[]
-- Result: ["a", "c"]

Important Notes: - Efficient for batch deletion - Works with both object keys and array elements - Only affects top-level keys/elements

- (integer) - Delete Array Element

Function Signature: - jsonb - integer → jsonb

Description: Deletes the array element with the specified index. Negative integers count from the end. Throws an error if JSON value is not an array.

Usage Examples: 

-- Delete element at index 1
'["a", "b"]'::jsonb - 1
-- Result: ["a"]

-- Delete last element (index -1)
'["a", "b", "c"]'::jsonb - 1
-- Result: ["a", "b"]

-- Error on non-array
'{"a": 1}'::jsonb - 0
-- Result: ERROR: cannot delete from object

Important Notes: - Only works on arrays - Supports negative indexing - Throws error for non-array values

#- - Delete at Path

Function Signature: - jsonb #- text[] → jsonb

Description: Deletes the field or array element at the specified path, where path elements can be either field keys or array indexes.

Usage Examples: 

-- Delete nested field
'["a", {"b":1}]'::jsonb #- '{1,b}'
-- Result: ["a", {}]

-- Delete nested array element
'{"data": {"items": [1,2,3,4]}}'::jsonb #- '{data,items,2}'
-- Result: {"data": {"items": [1, 2, 4]}}

Important Notes: - Works with nested structures - Returns NULL if path doesn't exist - Can delete deep nested elements - Path must be valid

@? - JSON Path Exists

Function Signature: - jsonb @? jsonpath → boolean

Description: Tests whether a JSON path returns any item for the specified JSON value. Only useful with SQL-standard JSON path expressions, not predicate check expressions.

Usage Examples: 

-- Check if any array element > 2
'{"a":[1,2,3,4,5]}'::jsonb @? '$.a[*] ? (@ > 2)'
-- Result: t

-- Check if path matches
'{"users": [{"name": "John"}, {"name": "Jane"}]}'::jsonb @? '$.users[*].name'
-- Result: t

Important Notes: - Suppresses errors like missing fields - Only for SQL-standard path expressions - Use @@ for predicate check expressions - Useful for conditional queries

@@ - JSON Path Predicate

Function Signature: - jsonb @@ jsonpath → boolean

Description: Returns the result of a JSON path predicate check for the specified JSON value. Only useful with predicate check expressions.

Usage Examples: 

-- Check predicate on array
'{"a":[1,2,3,4,5]}'::jsonb @@ '$.a[*] > 2'
-- Result: t

-- Check if all elements meet condition
'{"values": [1,2,3,4,5]}'::jsonb @@ '$.values[*] < 10'
-- Result: t

Important Notes: - Returns NULL if path result is not single boolean - Suppresses structural errors - Use @? for SQL-standard path expressions - Requires predicate expressions

3. JSON Creation Functions

to_json - Convert to JSON

Function Signature: - to_json (anyelement) → json - to_jsonb (anyelement) → jsonb

Description: Converts any SQL value to JSON or JSONB. Arrays and composites are converted recursively to arrays and objects. Numbers, booleans, and nulls are converted directly. Other scalars are converted to JSON strings.

Usage Examples: 

-- Convert text with escaping
to_json('Fred said "Hi."'::text)
-- Result: "Fred said \"Hi.\""

-- Convert row to JSON object
to_jsonb(row(42, 'Fred said "Hi."'::text))
-- Result: {"f1": 42, "f2": "Fred said \"Hi.\""}

-- Convert array
to_json(ARRAY[1, 2, 3])
-- Result: [1, 2, 3]

Important Notes: - Multidimensional arrays become arrays of arrays - Uses cast functions when available - Escapes strings as needed for valid JSON - Preserves data types appropriately

array_to_json - Convert Array to JSON

Function Signature: - array_to_json (anyarray [, boolean]) → json

Description: Converts an SQL array to a JSON array. Same behavior as to_json except line feeds are added between top-level elements if the optional boolean parameter is true.

Usage Examples: 

-- Convert 2D array
array_to_json('{{1,5},{99,100}}'::int[])
-- Result: [[1,5],[99,100]]

-- Convert with pretty formatting
array_to_json('{{1,5},{99,100}}'::int[], true)
-- Result: [[1,5],
--          [99,100]]

-- Convert simple array
array_to_json(ARRAY[1, 2, 3, 4])
-- Result: [1, 2, 3, 4]

Important Notes: - Optional boolean for pretty formatting - Preserves array structure - Works with multidimensional arrays - Second parameter adds line breaks

json_array - Construct JSON Array

Function Signature: 

json_array ([ { value_expression [FORMAT JSON] } [, ...] ] [ { NULL | ABSENT } ON NULL ] [ RETURNING data_type [ FORMAT JSON [ ENCODING UTF8 ] ] ])
json_array ([ query_expression ] [ RETURNING data_type [ FORMAT JSON [ ENCODING UTF8 ] ] ])

Description: Constructs a JSON array from value expressions or query results. If ABSENT ON NULL is specified, NULL values are ignored.

Usage Examples: 

-- Build from values
json_array(1, true, json '{"a":null}')
-- Result: [1, true, {"a":null}]

-- Build from query
json_array(SELECT * FROM (VALUES(1),(2)) t)
-- Result: [1, 2]

-- With null handling
json_array(1, NULL, 3 ABSENT ON NULL)
-- Result: [1, 3]

-- Return as jsonb
json_array(1, 2, 3 RETURNING jsonb)
-- Result: [1, 2, 3]

Important Notes: - Can use query expressions for array creation - Supports null handling options - Flexible return type specification - Always ignores NULL in query expressions

row_to_json - Convert Row to JSON

Function Signature: - row_to_json (record [, boolean]) → json

Description: Converts an SQL composite value to a JSON object. Same behavior as to_json except line feeds are added between top-level elements if the optional boolean parameter is true.

Usage Examples: 

-- Convert simple row
row_to_json(row(1,'foo'))
-- Result: {"f1":1,"f2":"foo"}

-- Convert with pretty formatting
row_to_json(row(1,'foo'), true)
-- Result: {"f1":1,
--          "f2":"foo"}

-- Convert table row
row_to_json(SELECT 1 as id, 'John' as name)
-- Result: {"id":1,"name":"John"}

Important Notes: - Uses column names as JSON keys - Supports pretty formatting - Recursive conversion of nested structures - Column names must be valid JSON keys

json_build_array - Build Array from Arguments

Function Signature: - json_build_array (VARIADIC "any") → json - jsonb_build_array (VARIADIC "any") → jsonb

Description: Builds a possibly-heterogeneously-typed JSON array from a variadic argument list. Each argument is converted as per to_json or to_jsonb.

Usage Examples: 

-- Build mixed type array
json_build_array(1, 2, 'foo', 4, 5)
-- Result: [1, 2, "foo", 4, 5]

-- Build jsonb array
jsonb_build_array(true, null, 'text', 42)
-- Result: [true, null, "text", 42]

-- Build nested array
json_build_array(1, json_build_array(2, 3))
-- Result: [1, [2, 3]]

Important Notes: - Supports mixed data types - Flexible argument list - Uses standard JSON conversion rules - Can create nested structures

json_build_object - Build Object from Arguments

Function Signature: - json_build_object (VARIADIC "any") → json - jsonb_build_object (VARIADIC "any") → jsonb

Description: Builds a JSON object from a variadic argument list. Arguments consist of alternating keys and values. Key arguments are coerced to text; value arguments are converted as per to_json or to_jsonb.

Usage Examples: 

-- Build simple object
json_build_object('foo', 1, 'bar', 2)
-- Result: {"foo": 1, "bar": 2}

-- Build with mixed types
json_build_object('foo', 1, 2, row(3,'bar'))
-- Result: {"foo" : 1, "2" : {"f1":3,"f2":"bar"}}

-- Build nested object
jsonb_build_object('user', jsonb_build_object('name', 'John', 'age', 30))
-- Result: {"user": {"name": "John", "age": 30}}

Important Notes: - Expects alternating key-value pairs - Keys are automatically converted to text - Supports complex nested structures - Duplicate keys allowed (last one wins)

json_object - Construct JSON Object

Function Signature: 

json_object ([ { key_expression { VALUE | ':' } value_expression [ FORMAT JSON [ ENCODING UTF8 ] ] } [, ...] ] [ { NULL | ABSENT } ON NULL ] [ { WITH | WITHOUT } UNIQUE [ KEYS ] ] [ RETURNING data_type [ FORMAT JSON [ ENCODING UTF8 ] ] ])

Description: Constructs a JSON object from key/value pairs. WITH UNIQUE KEYS enforces no duplicate keys. ABSENT ON NULL omits pairs with null values.

Usage Examples: 

-- Build with VALUE syntax
json_object('code' VALUE 'P123', 'title': 'Jaws')
-- Result: {"code" : "P123", "title" : "Jaws"}

-- With null handling
json_object('a' VALUE 'b', 'c' VALUE NULL ABSENT ON NULL)
-- Result: {"a": "b"}

-- With unique keys
json_object('a' VALUE 1, 'a' VALUE 2 WITH UNIQUE KEYS)
-- Result: ERROR: duplicate JSON object key

-- Return as jsonb
json_object('key' VALUE 'value' RETURNING jsonb)
-- Result: {"key": "value"}

Important Notes: - Supports both VALUE and : syntax - Handles null values flexibly - Can enforce unique key constraints - Flexible return type specification

json_object (from text array)

Function Signature: - json_object (text[]) → json - jsonb_object (text[]) → jsonb

Description: Builds a JSON object from a text array. Array must have even number of members (alternating key/value pairs) or be two-dimensional with pairs.

Usage Examples: 

-- Build from 1D array
json_object('{a, 1, b, "def", c, 3.5}')
-- Result: {"a" : "1", "b" : "def", "c" : "3.5"}

-- Build from 2D array
json_object('{{a, 1}, {b, "def"}, {c, 3.5}}')
-- Result: {"a" : "1", "b" : "def", "c" : "3.5"}

-- Build jsonb object
jsonb_object('{name, John, age, 30}')
-- Result: {"age": "30", "name": "John"}

Important Notes: - All values become JSON strings - Supports 1D and 2D array formats - Requires even number of elements for 1D arrays - Values are always text representation

json_object (separate arrays)

Function Signature: - json_object (keys text[], values text[]) → json - jsonb_object (keys text[], values text[]) → jsonb

Description: Takes keys and values pairwise from separate text arrays.

Usage Examples: 

-- Build from separate arrays
json_object('{a,b}', '{1,2}')
-- Result: {"a": "1", "b": "2"}

-- Build with more elements
json_object('{name,age,city}', '{John,30,Boston}')
-- Result: {"name": "John", "age": "30", "city": "Boston"}

-- Build jsonb
jsonb_object(ARRAY['x', 'y'], ARRAY['10', '20'])
-- Result: {"x": "10", "y": "20"}

Important Notes: - Keys and values come from separate arrays - Arrays must have same length - All values become JSON strings - Useful for column-based data

json - Parse JSON from String

Function Signature: - json (expression [FORMAT JSON [ENCODING UTF8]] [ { WITH | WITHOUT } UNIQUE [ KEYS ] ]) → json

Description: Converts a text or bytea string into a JSON value. If WITH UNIQUE is specified, expression must not contain duplicate object keys.

Usage Examples: 

-- Parse JSON string
json('{"a":123, "b":[true,"foo"]}')
-- Result: {"a":123, "b":[true,"foo"]}

-- Allow duplicate keys
json('{"a":123, "b":[true,"foo"], "a":"bar"}')
-- Result: {"a":123, "b":[true,"foo"], "a":"bar"}

-- Enforce unique keys
json('{"a":1, "a":2}' WITH UNIQUE KEYS)
-- Result: ERROR: duplicate JSON object key

-- Handle NULL input
json(NULL)
-- Result: NULL

Important Notes: - Returns SQL NULL for NULL input - Can enforce unique keys - Handles UTF8 encoded bytea - Validates JSON syntax

json_scalar - Convert to JSON Scalar

Function Signature: - json_scalar (expression)

Description: Converts a SQL scalar value into a JSON scalar value. Numbers and booleans become JSON numbers/booleans. Other values become JSON strings.

Usage Examples: 

-- Convert number
json_scalar(123.45)
-- Result: 123.45

-- Convert timestamp

Important Notes: - Returns SQL NULL for NULL input - Preserves number and boolean types - Converts other values to strings - Useful for type-specific conversion

4. SQL/JSON Testing Functions

IS JSON - JSON Type Test

Function Signature: - expression IS [NOT] JSON [ { VALUE | SCALAR | ARRAY | OBJECT } ] [ { WITH | WITHOUT } UNIQUE [ KEYS ] ]

Description: Tests whether expression can be parsed as JSON, optionally of a specific type. WITH UNIQUE KEYS tests for duplicate keys in objects.

Usage Examples: 

-- Basic JSON test
SELECT '123' IS JSON "json?",
       '"abc"' IS JSON SCALAR "scalar?",
       '{"a": "b"}' IS JSON OBJECT "object?",
       '[1,2]' IS JSON ARRAY "array?",
       'abc' IS JSON "json?"
-- Results: t, t, t, t, f

-- Test for duplicate keys
SELECT '[{"a":"1"}, {"b":"2","b":"3"}]'::json IS JSON ARRAY "array?",
       IS JSON ARRAY WITH UNIQUE KEYS "array w. UK?",
       IS JSON ARRAY WITHOUT UNIQUE KEYS "array w/o UK?"
-- Results: t, f, t

-- Test with NOT
SELECT 'not json' IS NOT JSON
-- Result: t

Important Notes: - Tests for valid JSON syntax - Can test for specific JSON types - Can check for duplicate keys - Returns false for invalid JSON

jsonb_set - Set Value at Path

Function Signature: - jsonb_set (target jsonb, path text[], new_value jsonb [, create_if_missing boolean]) → jsonb

Description: Returns target with the item designated by path replaced by new_value, or with new_value added if create_if_missing is true and the item doesn't exist.

Usage Examples: 

-- Replace existing value
jsonb_set('[{"f1":1,"f2":null},2,null,3]', '{0,f1}', '[2,3,4]', false)
-- Result: [{"f1": [2, 3, 4], "f2": null}, 2, null, 3]

-- Add new value (default behavior)
jsonb_set('[{"f1":1,"f2":null},2]', '{0,f3}', '[2,3,4]')
-- Result: [{"f1": 1, "f2": null, "f3": [2, 3, 4]}, 2]

-- Don't create if missing
jsonb_set('{"a": 1}', '{b}', '2', false)
-- Result: {"a": 1}

-- Add to array end
jsonb_set('[1,2,3]', '{3}', '4')
-- Result: [1, 2, 3, 4]

Important Notes: - All earlier path steps must exist - create_if_missing defaults to true - Negative integers count from end of arrays - Out of range array indexes add to beginning (negative) or end (positive)

jsonb_set_lax - Set Value at Path with Null Handling

Function Signature: - jsonb_set_lax (target jsonb, path text[], new_value jsonb [, create_if_missing boolean [, null_value_treatment text]]) → jsonb

Description: Like jsonb_set, but handles NULL new_value according to null_value_treatment: 'raise_exception', 'use_json_null', 'delete_key', or 'return_target'.

Usage Examples: 

-- Use JSON null (default)
jsonb_set_lax('[{"f1":1,"f2":null},2,null,3]', '{0,f1}', null)
-- Result: [{"f1": null, "f2": null}, 2, null, 3]

-- Return target unchanged
jsonb_set_lax('[{"f1":99,"f2":null},2]', '{0,f3}', null, true, 'return_target')
-- Result: [{"f1": 99, "f2": null}, 2]

-- Delete key
jsonb_set_lax('{"a": 1, "b": 2}', '{b}', null, false, 'delete_key')
-- Result: {"a": 1}

-- Raise exception
jsonb_set_lax('{"a": 1}', '{a}', null, false, 'raise_exception')
-- Result: ERROR: cannot set null at path

Important Notes: - Default null_value_treatment is 'use_json_null' - 'delete_key' removes the key - 'return_target' leaves original unchanged - 'raise_exception' throws error on null

jsonb_insert - Insert Value at Path

Function Signature: - jsonb_insert (target jsonb, path text[], new_value jsonb [, insert_after boolean]) → jsonb

Description: Returns target with new_value inserted. For array elements, inserts before (default) or after the specified index. For object fields, inserts only if key doesn't exist.

-- Insert before array element

-- Insert object field

-- Result: {"a": 1, "b": 2, "c": 3}

-- Don't insert if key exists
jsonb_insert('{"a": 1}', '{a}', '2')
-- Result: {"a": 1}

-- Add to array end
jsonb_insert('{"a": [1,2]}', '{a, 2}', '3')
-- Result: {"a": [1, 2, 3]}

Important Notes: - insert_after defaults to false - Only inserts if key doesn't exist for objects - All earlier path steps must exist - Negative integers count from end of arrays

json_strip_nulls - Remove Null Values

Function Signature: - json_strip_nulls (target json [,strip_in_arrays boolean]) → json - jsonb_strip_nulls (target jsonb [,strip_in_arrays boolean]) → jsonb

jsonb_path_exists - Test JSON Path Exists

Function Signature: - jsonb_path_exists (target jsonb, path jsonpath [, vars jsonb [, silent boolean]]) → boolean

Description: Checks whether the JSON path returns any item for the specified JSON value. vars provides named values for path variables.

Usage Examples: 

-- Basic path check
jsonb_path_exists('{"a":[1,2,3,4,5]}', '$.a[*] ? (@ >= 2 && @ <= 4)')
-- Result: t

-- With variables
jsonb_path_exists('{"a":[1,2,3,4,5]}',
  '$.a[*] ? (@ >= $min && @ <= $max)',
  '{"min":2, "max":4}')
-- Result: t

-- Silent mode
jsonb_path_exists('{"data": 42}', '$.missing[*]', null, true)
-- Result: f

Important Notes: - Only works with SQL-standard path expressions - vars must be JSON object - silent suppresses errors like @? and @@ operators - Returns false if no match found

jsonb_path_match - Test JSON Path Predicate

Function Signature: - jsonb_path_match (target jsonb, path jsonpath [, vars jsonb [, silent boolean]]) → boolean

Description: Returns the SQL boolean result of a JSON path predicate check for the specified JSON value.

Usage Examples: 

-- Check predicate
jsonb_path_match('{"a":[1,2,3,4,5]}',
  'exists($.a[*] ? (@ >= $min && @ <= $max))',
  '{"min":2, "max":4}')
-- Result: t

-- Complex predicate
jsonb_path_match('{"users": [{"age": 25}, {"age": 35}]}',
  'all($.users[*] ? (@.age >= 18))')
-- Result: t

-- With silent mode
jsonb_path_match('{"data": "not a number"}', '$.data > 5', null, true)
-- Result: NULL

Important Notes: - Only works with predicate check expressions - Returns NULL if path result is not single boolean - Same vars and silent behavior as path_exists - Useful for validation queries

Important Notes: - Returns set of matching values - Works with both standard and predicate expressions - Returns true/false/null for predicate expressions - Powerful for complex JSON queries

6. Timezone-Aware JSON Path Functions

These functions behave like their non-_tz counterparts but support comparisons of date/time values requiring timezone-aware conversions. They are marked as stable (cannot be used in indexes) due to TimeZone setting dependency.

jsonb_path_exists_tz

Function Signature: - jsonb_path_exists_tz (target jsonb, path jsonpath [, vars jsonb [, silent boolean]]) → boolean

Usage Examples: 

-- Timezone-aware comparison
jsonb_path_exists_tz('["2015-08-01 12:00:00-05"]',
  '$[*] ? (@.datetime() < "2015-08-02".datetime())')
-- Result: t

-- With timezone in data
jsonb_path_exists_tz('["2023-01-01T10:00:00+00:00"]',
  '$[*] ? (@.datetime() < "2023-01-01T09:00:00+00:00".datetime())')
-- Result: f

Important Notes: - Supports timezone-aware datetime comparisons - Stable function (cannot be used in indexes) - Non-_tz versions are immutable but throw errors on timezone comparisons - Result depends on current TimeZone setting

Other Timezone-Aware Functions

  • jsonb_path_match_tz (target jsonb, path jsonpath [, vars jsonb [, silent boolean]]) → boolean
  • jsonb_path_query_tz (target jsonb, path jsonpath [, vars jsonb [, silent boolean]]) → setof jsonb
  • jsonb_path_query_array_tz (target jsonb, path jsonpath [, vars jsonb [, silent boolean]]) → jsonb
  • jsonb_path_query_first_tz (target jsonb, path jsonpath [, vars jsonb [, silent boolean]]) → jsonb

All have the same timezone-aware behavior as jsonb_path_exists_tz.

Usage Examples: 

-- Query with timezone
SELECT * FROM jsonb_path_query_tz('["2023-01-01T10:00:00+00:00"]',
  '$[*] ? (@.datetime() > "2023-01-01T09:00:00+00:00".datetime())')
-- Results:
//  jsonb_path_query_tz

-- Match with timezone
jsonb_path_match_tz('["2023-01-01T12:00:00+05:00"]',

Summary

PostgreSQL provides a comprehensive set of JSON functions and operators that allow you to:

  1. Create JSON data from SQL values using conversion functions
  2. Extract and manipulate JSON values using operators and functions
  3. Query and filter JSON data using SQL/JSON path expressions
  4. Process JSON arrays and objects efficiently
  5. Handle timezone-aware date/time comparisons
  6. Validate and test JSON structures

The functions are split between json (text-based, preserves formatting) and jsonb (binary, optimized for processing) types, with most operations available for both types but some advanced features only available for jsonb.

For best performance, use jsonb for data that will be frequently queried or modified, and use indexing with the appropriate operators (@>, ?, ?&, ?|) for efficient searches.
