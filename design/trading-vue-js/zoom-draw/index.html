Zoom, pan, and drawing object visibility

This document explains what happens when the user zooms or pans the chart, how visible candlesticks are determined, and how drawing objects handle elements that extend outside the visible range.

Variables recalculated on zoom/pan

Primary state change: range

The core variable that changes is the time range (range):

Variable Meaning Units
range[0] Start time of visible window Timestamp or index
range[1] End time of visible window Timestamp or index

Zoom: Changes the span between range[0] and range[1] - Zoom in: Decreases the span (fewer candles visible) - Zoom out: Increases the span (more candles visible)

Pan: Shifts both range[0] and range[1] by the same amount

Cascading recalculation chain

When range changes, the following cascade occurs:

range changes
    ↓
subset() - Filter visible candlestick data
    ↓
update_layout() - Recalculate layout with new range
    ↓
redraw() - Render updated view

Key recalculated variables

1. Data subset (sub) - Filtered subset of OHLCV data within range - Contains only candlesticks that can potentially be visible

2. Layout variables (X-axis) - spacex = width - sidebar — drawable horizontal pixels - px_step = spacex / capacity — pixels per candle step - t2screen(t) — coordinate transformation: (t - range[0]) * r - 0.5 - xs — array of X-axis grid line positions

3. Layout variables (Y-axis) - $_hi — high price value (possibly expanded) - $_lo — low price value (possibly expanded) - A (scale) = -height / ($_hi - $_lo) for linear scale - B (offset) = -$_hi * A - $2screen(y) — coordinate transformation: y * A + B - 0.5 - ys — array of Y-axis grid line positions

4. Pre-calculated candle positions The layout creates a candles[] array with screen coordinates for each candle: 

candles.push({
    x: screen_x,
    w: candle_width,
    o: screen_open_y,
    h: screen_high_y,
    l: screen_low_y,
    c: screen_close_y
})

These coordinates are cached to avoid recalculating during each redraw.

Candlestick visibility determination

How visible candlesticks are identified

The chart uses efficient data subsetting to identify which candlesticks belong in the visible range.

Filtering mechanism

// In Chart.vue subset() method
let [res, index] = this.filter(
    this.ohlcv,
    range[0] - this.interval,  // Padding: include one extra bar before
    range[1]
)

Two filtering methods are used depending on mode:

Time-based mode (standard): 

// In utils.js fast_filter()
fast_filter(arr, t1, t2) {
    let ia = new IndexedArray(arr, "0")  // Index by timestamp (column 0)
    let res = ia.getRange(t1, t2)        // Efficient range query
    let i0 = ia.valpos[t1].next         // Starting index for tracking
    return [res, i0]
}

Index-based mode (when indexBased: true): 

// In utils.js fast_filter_i()
fast_filter_i(arr, t1, t2) {
    let i1 = Math.floor(t1)
    let i2 = Math.floor(t2 + 1)
    let res = arr.slice(i1, i2)
    return [res, i1]
}

Process flow

  1. User zooms/pans → range updated
  2. Filter data → Create sub[] containing only candles in range
  3. Calculate layout → Convert each candle in sub[] to screen coordinates
  4. Render → Draw only candles from sub[]

Why this approach works

  • Efficiency: Only processes data that will be visible
  • Correctness: No wasted computation on off-screen elements
  • Smoothness: Small padding before range[0] prevents edge flicker

Example

Given range = [1600000000000, 1600086400000] (24 hours):

// Filter finds candles between these timestamps
sub = [
    [1600000000000, 100, 105, 98, 102, 1000],  // Inside range
    [1600016400000, 102, 110, 101, 108, 1200],  // Inside range
    [1600032800000, 108, 115, 105, 112, 900],   // Inside range
]
// Candles outside these timestamps are NOT in sub[]

Only these 3 candles are processed and drawn.

Drawing object visibility (lines, rectangles, etc.)

Question: Do we draw all elements or only visible ones?

Answer: Drawing objects draw ALL their data points, even if outside the visible range.

How it works in practice

Let's look at an example overlay:

// Example from Segment.vue
draw(ctx) {
    if (!this.p1 || !this.p2) return

    ctx.lineWidth = this.line_width
    ctx.strokeStyle = this.color
    ctx.beginPath()

    const layout = this.$props.layout

    // Convert BOTH endpoints to screen coordinates
    let x1 = layout.t2screen(this.p1[0])
    let y1 = layout.$2screen(this.p1[1])
    ctx.moveTo(x1, y1)

    let x2 = layout.t2screen(this.p2[0])
    let y2 = layout.$2screen(this.p2[1])
    ctx.lineTo(x2, y2)

    ctx.stroke()
}

What happens with off-screen points?

  1. All points are converted to screen coordinates using t2screen() and $2screen()
  2. Off-screen points get coordinates outside the canvas:
  3. x < 0 or x > width → outside horizontal bounds
  4. y < 0 or y > height → outside vertical bounds
  5. Canvas naturally clips the drawing at the canvas boundaries
  6. Portions of shapes inside the visible area are rendered

Example: Line extending beyond chart

// Data points: [t1, price1], [t2, price2]
// Point 1: t1 = 1600000000000 (inside range)
// Point 2: t2 = 1600172800000 (outside range)

// Screen conversion:
x1 = layout.t2screen(1600000000000)  // = 100 (inside canvas)
y1 = layout.$2screen(105)            // = 150 (inside canvas)

x2 = layout.t2screen(1600172800000)  // = 850 (outside canvas, width=800)
y2 = layout.$2screen(120)            // = 200 (inside canvas)

// Drawing: line from (100, 150) to (850, 200)
// Canvas clips at x=800, so only portion to x=800 is visible

Why this approach?

Advantages: - Simplicity: No need for complex intersection calculations - Correct clipping: Canvas handles partial rendering automatically - Smooth edges: Lines/rectangles properly terminate at chart boundaries

Considerations: - Minimal overhead: Converting a few points is cheap - Not inefficient: Drawing operations on off-screen coordinates are generally optimized by canvas - Alternative: Could pre-filter data, but complexity may outweigh benefits for most use cases

When pre-filtering might be beneficial

For overlays with very large datasets (e.g., thousands of data points), you might consider:

  1. Pre-filter by time range: Skip points clearly outside range
  2. Bbox culling: For complex shapes, check if shape intersects visible rectangle
  3. Spatial indexing: For many objects, use spatial data structures

But for typical trading chart overlays (trendlines, rectangles, a few dozen points), the current approach is adequate.

Summary: Visibility detection

Element type Visibility detection
Candlesticks Explicitly filtered: only sub[] (visible subset) is processed
Drawing objects Implicit clipping: all points drawn, canvas clips to bounds
Drawing objects Can optionally filter: check t2screen() result against canvas bounds
