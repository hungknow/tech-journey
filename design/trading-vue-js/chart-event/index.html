Chart mouse and keyboard events

This document describes every mouse and keyboard event that affects the chart: which variables are updated and what is affected afterward. The first section lists all variables and the events that affect them; the rest groups events by source and describes updates and effects in detail.

Variables and the events that affect them

crosshair_state (Chart: crosshair position and state)

  • crosshair_state.x, crosshair_state.y, crosshair_state.t, crosshair_state.y$, crosshair_state.grid_id, crosshair_state.values: mousemove (via cursor_changed and crosshair sync), mouseout (position effectively cleared), panstart (cursor_changed), panmove (cursor_changed; or crosshair coord only when mode is aim), tap (cursor_changed with mode explore), press (cursor_changed with mode aim).
  • crosshair_state.locked: mousedown (set true), mouseup (set false), panstart (set true), panend (set false).

visible_time_range (Chart: visible time or index window)

  • visible_time_range[0], visible_time_range[1]: panmove (when active_pan_drag is set), panend (via momentum_scroll on mobile), pinch, wheel (zoom or trackpad scroll), and in all cases via the subsequent range-changed handling in Chart.

visible_data_slice (Chart: data subset for the visible time range)

  • Updated whenever visible_time_range changes: same events as visible_time_range (panmove, panend with momentum_scroll, pinch, wheel), because range-changed handling overwrites visible_data_slice from the new range.

chart_has_focus (Chart: user has clicked inside the chart)

  • chart_has_focus: mousedown on root (set true), mouseleave on root (set false).

vertical_scale_per_grid (Chart: per-grid y scale and offset)

  • vertical_scale_per_grid[grid_id]: panmove (when active_pan_drag is set and y_transform is not auto; sidebar-transform is emitted and vertical scale is updated).

canvas_screen_offset (grid: canvas bounding rect offset for coordinate conversion)

  • canvas_screen_offset_x, canvas_screen_offset_y: mousemove, panmove on mobile, press on mobile (canvas bounding rect offset refreshed each time).

active_pan_drag (grid: active pan or drag gesture state)

  • active_pan_drag: panstart (set to drag state object), mouseup (null), panend (null), pinchstart (null).

active_pinch_zoom (grid: active pinch-zoom gesture state)

  • active_pinch_zoom: pinchstart (set to visible_time_range width and copy), pinchend (null).

momentum_scroll_animation (grid: pan_fade — follow-through after release)

  • momentum_scroll_animation: panend on mobile (may start when active_pan_drag was set), tap (stop), press (stop).

is_trackpad_gesture (grid: whether wheel event is from trackpad)

  • is_trackpad_gesture: wheel (set true when event has deltaX).

overlay_pointer_state (per overlay: pointer position and button state for overlay logic)

  • overlay_pointer_state.x, overlay_pointer_state.y, overlay_pointer_state.t, overlay_pointer_state.y$: mousemove (and on mobile, panmove and tap/press via synthetic mousemove).
  • overlay_pointer_state.pressed: mousedown (true), mouseup (false).

overlay_held_keys (per overlay: which keys are currently held)

  • held_keys_map[key]: keydown (set true for event.key; also emits key name if first press), keyup (set false for event.key).

chart_layout (Chart: grid dimensions and scales)

  • chart_layout: updated indirectly when visible_time_range, width, height, or vertical_scale_per_grid change; the events that change visible_time_range or vertical scale therefore affect chart_layout (panmove, panend with momentum_scroll, pinch, wheel, and sidebar-transform from panmove).

chart_has_focus_in_meta (passed to grid from Chart as meta.activated)

  • Same as chart_has_focus: mousedown on root (true), mouseleave on root (false). Used when handling wheel when SCROLL_WHEEL is 'click'.

Mouse events on the grid canvas

The grid canvas is the main chart area. It receives native mouse events (desktop) and forwards them to the grid and overlays.

mousemove

Used for — Moving the crosshair and reading values: the chart shows the price (or value) at the pointer and overlays can show tooltips or react to hover.

Context — Fires on the grid canvas when the pointer moves over the chart (desktop). On mobile, equivalent updates come from panmove and tap/press via synthetic mousemove.

Variables updated

  • cursor_changed payload (emitted): grid_id, x (event.layerX), y (event.layerY + layout offset). Chart receives this and may run crosshair sync.
  • canvas_screen_offset_x, canvas_screen_offset_y (grid): canvas bounding rect offset refreshed so screen coordinates are correct.
  • overlay_pointer_state (per overlay): x, y (layer coordinates), t (time at x), y$ (value at y).

Affected

  • Chart emits cursor-changed; Chart may set crosshair_state.mode and sync crosshair values, which updates crosshair_state.grid_id, crosshair_state.t, crosshair_state.values[grid.id], crosshair_state.x, crosshair_state.y, crosshair_state.y$.
  • Crosshair and overlays receive the new pointer position; crosshair visibility and overlay logic (e.g. tooltips) can react.
  • Grid redraws when crosshair_state changes so crosshair and overlay rendering stay in sync.

mouseout

Used for — Hiding the crosshair and clearing hover state when the pointer leaves the chart so the user sees that focus is no longer on the chart.

Context — Fires on the grid canvas when the pointer leaves the canvas (desktop only; mobile has no native mouseout).

Variables updated

  • cursor_changed payload (emitted): empty object. Chart still handles cursor-changed but with no coordinates.

Affected

  • Crosshair position is cleared or not updated; crosshair can hide and overlays can clear hover state.
  • Overlay pointer handlers receive mouseout; overlay logic can clear hover/tooltips.

mousedown

Used for — Starting a pan/drag or an overlay action: the crosshair is locked so it does not jump while dragging, and overlays (e.g. drawing tools) can begin a drag or selection.

Context — Fires on the grid canvas when the user presses the mouse button over the chart (desktop). On mobile, tap and press trigger equivalent behavior (synthetic mousedown).

Variables updated

  • overlay_pointer_state.pressed: set to true (after handlers run).
  • cursor_locked (emitted): true. Chart sets crosshair_state.locked = true (unless crosshair_state.scroll_lock is set).

Affected

  • Overlay renderers and pointer listeners receive mousedown; tools and overlays can start drag or selection.
  • If event is not default-prevented, Chart emits custom-event with grid-mousedown (grid_id and event). DataCube and extensions can react.
  • Crosshair is locked so pan/drag can start without the crosshair jumping.

mouseup

Used for — Ending a pan/drag or overlay action: the crosshair unlocks and can move with the pointer again, and overlays can finalize a drag or selection.

Context — Fires on the grid canvas when the user releases the mouse button (desktop). On mobile, panend clears drag state; overlay “click” is simulated after tap.

Variables updated

  • active_pan_drag (grid): set to null (drag state cleared).
  • cursor_locked (emitted): false. Chart sets crosshair_state.locked = false.
  • overlay_pointer_state.pressed: set to false (after handlers run).

Affected

  • Pan/drag ends; no further visible_time_range or transform updates from this pointer.
  • Overlay renderers and pointer listeners receive mouseup; tools can finish drag or selection.
  • Crosshair can move again with the pointer.

click (mobile only)

Used for — Letting overlays react to a tap as a single click (e.g. buttons, point-and-click tools) without changing crosshair or time range in the framework.

Context — Not bound on the canvas on desktop. On mobile, it is only fired from tap: a synthetic mousemove and mousedown run first, then a delayed click is sent to overlays.

Variables updated

  • None in the grid or Chart directly; overlays receive the synthetic click event.

Affected

  • Overlay renderers that handle click receive it (e.g. buttons, point-and-click tools). No crosshair or visible_time_range change from the framework.

Touch and gesture events (Hammer on grid canvas)

Hammer handles touch and pointer gestures on the same canvas. These run in addition to (or instead of) native mouse events on mobile.

panstart

Used for — Starting a pan or drag: the user can scroll the chart horizontally (change visible time range), shift the y-axis (if not auto-scaled), and the crosshair is locked at the touch point.

Context — Fires when the user touches the grid canvas and starts a pan (or on desktop, when a pointer drag is recognized as pan). Does not run if crosshair is scroll-locked or in aim mode (then only cursor position is reported).

Variables updated

  • active_pan_drag (grid): object with drag state: x, y (center + offset), r (visible_time_range copy), t (visible_time_range width), o (y_transform offset), y_r (y transform range), B (chart_layout.B), t0 (timestamp). Omitted if crosshair_state.scroll_lock or if crosshair_state.mode === 'aim' (then only crosshair coord is emitted).
  • cursor_changed (emitted): grid_id, x, y (center + offset).
  • cursor_locked (emitted): true.

Affected

  • Chart sets crosshair position and locks crosshair; pan/drag can move visible_time_range and/or vertical_scale_per_grid.
  • Subsequent panmove either updates visible_time_range (and optionally y) when active_pan_drag is set, or only updates crosshair position when mode is aim.

panmove

Used for — Updating the chart while panning or dragging: the visible time range (and optionally the y scale) moves with the finger or pointer, and the crosshair position is kept in sync for aim mode.

Context — Fires repeatedly while the user pans or drags on the grid canvas. On mobile, also drives a synthetic mousemove so overlays see pointer movement. If a pan was started (active_pan_drag set), this updates visible_time_range and possibly vertical_scale_per_grid; otherwise in aim mode it only updates crosshair position.

Variables updated

  • On mobile: canvas_screen_offset_x, canvas_screen_offset_y refreshed, and a synthetic mousemove (from touch) is sent to overlays so they see movement.
  • If active_pan_drag is set: visible_time_range[0], visible_time_range[1] are updated (and optionally sidebar-transform for y), then range is clamped and range-changed is emitted.
  • cursor_changed (emitted): grid_id, x, y (center + offset).
  • If no active_pan_drag and crosshair_state.mode === 'aim': cursor_changed with coord only.

Affected

  • visible_time_range and/or vertical_scale_per_grid change; Chart handles range-changed and updates visible_time_range, visible_data_slice, chart_layout; Grid redraws.
  • Sidebar can receive sidebar-transform and update scale/position.
  • Crosshair position stays in sync for crosshair and overlays.

panend

Used for — Ending a pan/drag: the crosshair unlocks and, on mobile, optional momentum scrolling can continue for a short time so the chart “coasts” after a fast swipe.

Context — Fires when the user lifts the finger or releases the pointer after a pan/drag on the grid canvas. On mobile, if the user was panning, a brief momentum_scroll_animation may run using the release velocity.

Variables updated

  • active_pan_drag (grid): set to null.
  • On mobile, if active_pan_drag was set: momentum_scroll_animation may start (updating visible_time_range[0], visible_time_range[1] and emitting range-changed until velocity decays).
  • cursor_locked (emitted): false.

Affected

  • Pan/drag ends; crosshair unlocks; optional momentum scroll (mobile) continues briefly via momentum_scroll_animation.

tap (mobile)

Used for — Treating a short touch as a click: the chart switches to explore mode (crosshair follows the tap), overlays receive mousemove, mousedown, and click, and any running momentum scroll is stopped so the tap is not mistaken for a pan.

Context — Fires on the grid canvas when the user taps without panning (mobile). Simulates a full mouse sequence (mousemove → mousedown → click) for overlays and sets crosshair_state.mode to explore.

Variables updated

  • Synthetic mousemove, mousedown, and delayed click are sent to overlays; cursor_changed emitted twice (empty then mode: 'explore'); grid redraws.
  • If momentum_scroll_animation was running, it is stopped.

Affected

  • Overlays get mousemove, mousedown, then click; crosshair_state.mode set to explore; grid redraws.

pinchstart

Used for — Preparing a pinch-zoom: the chart stores the current visible time range so the following pinch events can zoom in or out around the center without conflicting with an active pan.

Context — Fires when the user puts a second finger on the grid canvas (mobile). Any active pan is cancelled (active_pan_drag cleared); the current range width and bounds are stored for pinchzoom.

Variables updated

  • active_pan_drag (grid): set to null (pan cancelled).
  • active_pinch_zoom (grid): stores visible_time_range width and a copy of visible_time_range for pinchzoom.

Affected

  • Subsequent pinch events will zoom around center using this stored range.

pinchend

Used for — Ending a pinch-zoom: no further zoom is applied until the user starts a new pinch, so the chart stays at the last zoom level.

Context — Fires when the user lifts one finger so the pinch gesture ends (mobile). Clears active_pinch_zoom; no other chart state is updated.

Variables updated

  • active_pinch_zoom (grid): set to null.

Affected

  • Pinch zoom stops; no further visible_time_range updates from pinch until next pinchstart.

pinch

Used for — Zooming the chart in or out with two fingers: the visible time range shrinks (zoom in) or grows (zoom out) around the center, within min/max zoom limits.

Context — Fires repeatedly while the user pinches on the grid canvas (mobile), after pinchstart has stored the range. Scale is applied to the stored range; range-changed is emitted and the chart redraws.

Variables updated

  • If active_pinch_zoom is set: visible_time_range[0], visible_time_range[1] updated (zoom in/out around center), then range-changed emitted. Bounds are clamped by min/max zoom limits.

Affected

  • Chart handles range-changed and updates visible_time_range, visible_data_slice, chart_layout; grid and sidebar redraw.

press (mobile)

Used for — Long-press to “aim”: the crosshair locks at the press position (aim mode) so the user can read values without the crosshair moving, and overlays get a full mouse sequence (mousemove, mousedown, click) for long-press actions.

Context — Fires when the user holds a finger on the grid canvas long enough for Hammer to recognize a press (mobile). Stops any momentum scroll, refreshes canvas offset, sets crosshair mode to aim, and sends synthetic mousemove, mousedown, and click to overlays.

Variables updated

  • momentum_scroll_animation (grid): stopped if present.
  • canvas_screen_offset_x, canvas_screen_offset_y (grid): refreshed.
  • cursor_changed (emitted): with coord and mode: 'aim'.
  • Grid redraw is scheduled.
  • Synthetic mousemove, mousedown, and delayed click are sent to overlays.

Affected

  • Crosshair switches to aim mode (locked at press position); overlays get mousemove, mousedown, click; grid redraws.

Wheel (mouse wheel / trackpad on grid canvas)

Wheel is handled by Hamster on the grid canvas and drives zoom and scroll.

wheel

Used for — Zooming or scrolling the chart with the mouse wheel or trackpad: vertical wheel (or trackpad vertical) zooms in/out or scrolls the visible time range; horizontal trackpad scrolls the chart left/right. Optional “click-to-activate” (SCROLL_WHEEL 'click') requires a prior click inside the chart before wheel has effect.

Context — Fires when the user scrolls over the grid canvas (desktop and trackpad). Behavior depends on config (SCROLL_WHEEL, ZOOM_MODE) and whether the event has horizontal delta (trackpad). If ZOOM_MODE is 'tl' with ctrl or tl, rezoom-range can also update the y-axis.

Variables updated

  • is_trackpad_gesture (grid): set to true when deltaX is present and used to scale delta and choose scroll vs zoom behavior.
  • event.deltaX, event.deltaY: normalized from the event if not set.
  • If horizontal scroll (trackpad): visible_time_range[0], visible_time_range[1] updated (horizontal scroll), then range-changed emitted.
  • Otherwise (or in addition): visible_time_range[0], visible_time_range[1] updated (zoom or vertical scroll). In ZOOM_MODE 'tl' with ctrl or tl mode, rezoom-range is emitted with grid_id, z, diff1, diff2.
  • visible_time_range is clamped to data bounds and range-changed is emitted.

Affected

  • Chart handles range-changed and updates visible_time_range, visible_data_slice, chart_layout; grid and botbar redraw.
  • If rezoom-range is emitted, the section forwards to the sidebar for y-axis rezoom.
  • Wheel is optionally prevented (when wmode is not 'pass', and when wmode is 'click' only if chart_has_focus_in_meta).

Keyboard events

Keyboard events are global (window). They are forwarded to registered listeners; each grid section receives them only when that grid is active.

keydown

Used for — Letting overlays react to key presses (e.g. Escape to cancel a tool, Enter to confirm, modifier keys for multi-step actions). The “active” grid (the one under the crosshair) receives the event; overlays can read which keys are held via held_keys_map.

Context — Fires on the window when any key is pressed. Only the grid whose crosshair_state.grid_id matches and has a defined crosshair_state.t is considered active and receives keydown; other grids ignore it.

Variables updated

  • overlay_held_keys (per overlay): for the event’s key, held_keys_map[key] set to true. If the key was not already pressed, the key name is also emitted as a custom event (e.g. Escape).

Affected

  • Only the grid with matching crosshair_state.grid_id and defined crosshair_state.t is active; that grid forwards keydown to its overlays. Overlay renderers and key listeners receive keydown; overlays can cancel drag, submit, etc.

keyup

Used for — Letting overlays know a key was released (e.g. shift, escape, or shortcut keys) so they can clear key-held state or finish an action.

Context — Fires on the window when any key is released. Only the active grid (same as keydown) receives keyup; overlay held_keys_map is updated so overlays can query which keys are still held.

Variables updated

  • overlay_held_keys (per overlay): held_keys_map[event.key] set to false.

Affected

  • Active grid’s overlays receive keyup; overlays can clear key-held state (e.g. shift, escape).

keypress

Used for — Letting overlays handle character input (e.g. typing in a text tool or search box). The framework does not change crosshair or range; overlays can use it for their own UI.

Context — Fires on the window when a character key is pressed (after keydown). Forwarded to the active grid’s overlays only; no built-in chart state is updated.

Variables updated

  • None in the framework; only forwarded to overlay renderers.

Affected

  • Overlays can handle character input (e.g. text tools). No crosshair_state or visible_time_range change in core.

Root-level events (TradingVue container)

The root div of TradingVue listens to two mouse events to track whether the user is “inside” the chart.

mousedown (root)

Used for — Marking that the user has interacted with the chart so that, when SCROLL_WHEEL is 'click', wheel zoom/scroll is enabled only after this click. Avoids accidental zoom when the pointer is over the chart but the user intended to scroll the page.

Context — Fires on the root chart container (the outer div), not on the grid canvas, when the user presses the mouse button anywhere inside the chart area (toolbar, legend, canvas, etc.). Sets chart_has_focus so wheel can be allowed when SCROLL_WHEEL is 'click'.

Variables updated

  • chart_has_focus (Chart): set to true.

Affected

  • Chart’s chart_has_focus_in_meta becomes true; passed to grid as meta.activated. When SCROLL_WHEEL is 'click', wheel zoom/scroll is only applied after the user has clicked inside the chart once.

mouseleave (root)

Used for — Clearing “chart has focus” when the pointer leaves the chart so that, with SCROLL_WHEEL 'click', wheel over the chart is ignored again until the user clicks inside. Keeps wheel behavior consistent with user intent (scroll page vs. zoom chart).

Context — Fires on the root chart container when the pointer leaves that container (e.g. moves to the page margin, another widget, or the browser chrome). Chart no longer treats the user as “focused” on the chart.

Variables updated

  • chart_has_focus (Chart): set to false.

Affected

  • chart_has_focus_in_meta becomes false; with SCROLL_WHEEL 'click', wheel on the chart will again be ignored until the user mousedowns inside the root.

Summary of shared state touched by events

  • crosshair_state: x, y, t, y$, grid_id, locked, mode, values — updated by cursor_changed and cursor_locked; drives crosshair, overlay values, and which grid gets keyboard events.
  • visible_time_range: time (or index) window — updated by range_changed from wheel, pan, pinch, trackpad_scroll, momentum_scroll_animation; drives chart_layout, visible_data_slice, and redraws.
  • vertical_scale_per_grid: per-grid y scale/position — updated by sidebar-transform from pan/drag when y_transform is not auto; drives chart_layout and sidebar.
  • active_pan_drag / active_pinch_zoom: internal gesture state for pan and pinch; not exposed outside grid.
  • overlay_pointer_state: x, y, t, y$, pressed — used by overlay logic and drawing.
  • overlay_held_keys (held_keys_map): which keys are held — used by overlay logic.
  • chart_has_focus: whether the user has clicked inside the chart; gates wheel when SCROLL_WHEEL is 'click'.
