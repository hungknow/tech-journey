Axis range management: grid, labels, and axis lines

This document describes how a trading chart manages the range of the X (time) and Y (price) axes, and how these ranges are used to draw grid lines, axis labels, and axis lines. It focuses on mutual concepts that can be applied to any 2D chart in any framework or language.

Context

  • Data range: The subset of data currently visible, defined by time_range and price_high/price_low.
  • Chart area: The pixel rectangle where the chart is drawn (chart_width × chart_height).
  • Goal: Draw a useful grid and axis labels that help the user read values and understand the scale.

The grid and labels must be: - Readable: Not too dense, not too sparse. - Accurate: Labels match the actual values at grid lines. - Adaptive: Adjust to the current range and size. - Consistent: Use intervals that make sense (e.g., 1, 2, 5, 10, 20, 50, 100).

Main variables (what to track)

These are the inputs your chart keeps for axis management:

Variable Meaning Units / notes
time_range Visible time window [t_min, t_max] (same units as data)
price_high Upper bound of visible price range Data price units
price_low Lower bound of visible price range Data price units
chart_width Chart drawing width (X axis length) Pixels
chart_height Chart drawing height (Y axis length) Pixels
use_log_scale Use log(price) for Y axis Boolean
font_config Font settings for labels Family, size, etc.
axis_padding Space between chart area and axis labels Pixels

Optional config (tunable constants):

  • target_grid_count — ideal number of grid lines (e.g., 5–10).
  • min_grid_spacing — minimum pixel spacing between grid lines (e.g., 40 px).
  • label_format_func — function to format values for display.

X-axis (time): grid lines and labels

Challenge

Time is irregular: months have 28–31 days, trading days skip weekends, etc. We need grid lines at regular human-readable intervals (e.g., 1 hour, 1 day, 1 week, 1 month).

Algorithm: choose time grid interval

  1. Calculate time span: time_span = time_range[1] - time_range[0].
  2. Estimate ideal interval: ideal_interval = time_span / target_grid_count.
  3. Find nearest "nice" time interval: Use a table of preferred intervals based on magnitude: 
    const TIME_INTERVALS = [
  // milliseconds: 1, 5, 10, 30
  // seconds: 1, 5, 10, 30
  // minutes: 1, 5, 10, 15, 30
  // hours: 1, 2, 3, 4, 6, 8, 12
  // days: 1, 2, 3, 7, 14
  // months: 1, 2, 3, 6
  // years: 1, 2, 5, 10
]
    Find the smallest interval from this table where interval >= ideal_interval.
  4. Check pixel spacing: Calculate pixel_spacing = interval * px_per_time (from px_per_time = chart_width / time_span). If pixel_spacing < min_grid_spacing, choose the next larger interval.

Example: finding nearest nice time interval

Suppose: - time_range = [0, 86400000] (one day in milliseconds: from 00:00 to 24:00) - target_grid_count = 6 - chart_width = 1200 pixels - min_grid_spacing = 50 pixels

Step 1: Calculate time span 

time_span = 86400000 - 0 = 86400000 ms

Step 2: Estimate ideal interval 

ideal_interval = 86400000 / 6 = 14400000 ms (exactly 4 hours)

Step 3: Find nearest nice time interval 

TIME_INTERVALS sorted by duration (ms):
1 ms, 5 ms, 10 ms, 30 ms,
1s=1000, 5s=5000, 10s=10000, 30s=30000,
1min=60000, 5min=300000, 10min=600000, 15min=900000, 30min=1800000,
1h=3600000, 2h=7200000, 3h=10800000, 4h=14400000, 6h=21600000, 8h=28800000, 12h=43200000,
1d=86400000, 2d=172800000, ...

We want smallest interval >= 14400000.
- 1h = 3600000 < 14400000 (too small)
- 2h = 7200000 < 14400000 (too small)
- 3h = 10800000 < 14400000 (too small)
- 4h = 14400000 >= 14400000 ✓

grid_interval = 4 hours = 14400000 ms

Step 4: Check pixel spacing 

px_per_time = 1200 / 86400000 = 0.000013889 pixels/ms
pixel_spacing = 14400000 * 0.000013889 = 200 pixels

200 px >= 50 px (min_grid_spacing) ✓

Result: Use 4-hour intervals

Another example: If ideal_interval = 17000000 (~4.72 hours)

Find smallest interval >= 17000000:
- 4h = 14400000 < 17000000 (too small)
- 6h = 21600000 >= 17000000 ✓

grid_interval = 6 hours

Check pixel spacing:
pixel_spacing = 21600000 * 0.000013889 = 300 pixels >= 50 px ✓

One more example: Very small range 

time_range = [0, 300000] (5 minutes)
target_grid_count = 5

ideal_interval = 300000 / 5 = 60000 ms (1 minute)

Find smallest interval >= 60000:
- 30s = 30000 < 60000 (too small)
- 1min = 60000 >= 60000 ✓

grid_interval = 1 minute = 60000 ms

Generate X grid lines

Once we have grid_interval:

  1. Align start: Find the first grid time >= time_range[0] that aligns with the interval (e.g., round to nearest hour/day/month).
  2. Generate times: Iterate from start to time_range[1], adding grid_interval each step.
  3. Convert to pixels: For each time t, calculate x = time_to_screen(t) (same formula as for candlesticks).

X-axis labels

For each grid line at time t:

  1. Format label: Based on the grid interval, choose an appropriate format:
  2. Sub-minute: show seconds
  3. Minutes/hours within a day: show HH:MM
  4. Multiple days: show MM/DD or DD/MM
  5. Months/years: show MMM YYYY or YYYY
  6. Position label: Below the X-axis line, at x = time_to_screen(t).
  7. Avoid overlap: If labels are too close, skip some (e.g., show every other label).

X-axis line

Draw a horizontal line at y = chart_height + axis_padding/2 (or just at y = chart_height if no padding). The axis line spans from x = 0 to x = chart_width.

Y-axis (price): grid lines and labels

Algorithm: choose price grid interval (linear scale)

For linear scale, we use the "nice numbers" algorithm to find aesthetically pleasing intervals:

  1. Calculate price span: price_span = price_high - price_low.
  2. Estimate ideal interval: ideal_interval = price_span / target_grid_count.
  3. Find "nice" interval:
  4. Compute exponent = floor(log10(ideal_interval)).
  5. Compute fraction = ideal_interval / 10^exponent (value between 1 and 10).
  6. Find nearest nice fraction: nice_fraction ∈ {1, 2, 5, 10}.
  7. grid_interval = nice_fraction × 10^exponent.

Example: - price_span = 87, target_grid_count = 5. - ideal_interval = 87 / 5 = 17.4. - exponent = floor(log10(17.4)) = 1. - fraction = 17.4 / 10 = 1.74. - Nearest nice fractions: 1, 2, 5. 1.74 is closest to 2. - grid_interval = 2 × 10 = 20.

Algorithm: choose price grid interval (log scale)

For log scale, we want grid lines at equal percentage intervals (e.g., 1%, 2%, 5%, 10%):

  1. Calculate log span: log_span = log(price_high) - log(price_low).
  2. Estimate ideal log interval: ideal_log_interval = log_span / target_grid_count.
  3. Find nice percentage interval: Use the same "nice numbers" algorithm on the log interval, then convert to percentage:
  4. grid_log_interval = nice_number(ideal_log_interval).
  5. grid_percentage = exp(grid_log_interval) - 1 (e.g., 0.01 for 1%, 0.05 for 5%).
  6. Alternative: use fixed percentage steps: Choose from {1%, 2%, 5%, 10%, 20%, 25%, 50%}.

Generate Y grid lines (linear)

Once we have grid_interval:

  1. Align start: Find the first grid price <= price_low that aligns with the interval: start_price = floor(price_low / grid_interval) * grid_interval.
  2. Generate prices: Iterate from start_price upward, adding grid_interval each step, until >= price_high.
  3. Convert to pixels: For each price p, calculate y = price_to_screen(p) using the price_scale and price_offset from candlestick scaling.

Generate Y grid lines (log)

For log scale, grid lines are at constant percentage steps:

  1. Calculate start: Use price_low or round down to a nice number.
  2. Generate prices: Each step multiplies by (1 + grid_percentage):
  3. price_0 = start_price
  4. price_1 = price_0 × (1 + grid_percentage)
  5. price_2 = price_1 × (1 + grid_percentage)
  6. ...
  7. Convert to pixels: Use y = log(price) * price_scale + price_offset.

Alternative for log: Draw grid lines at powers of 10 (1, 10, 100, 1000...) and optionally at intermediate values (2, 5, 20, 50, 200, 500...).

Y-axis labels

For each grid line at price p:

  1. Format label: Use label_format_func(p). Common formats:
  2. Fixed decimal places: p.toFixed(2)
  3. Precision based on interval: fewer decimals for large intervals.
  4. Position label: To the left of the Y-axis line, at y = price_to_screen(p).
  5. Right-align text: Align labels to the right edge of the axis area.

Y-axis line

Draw a vertical line at x = -axis_padding/2 (or at x = 0 if no padding). The axis line spans from y = 0 to y = chart_height.

Grid lines in the chart area

The grid lines extend across the chart area:

  • X grid lines: Vertical lines from (x, 0) to (x, chart_height) at each time grid point.
  • Y grid lines: Horizontal lines from (0, y) to (chart_width, y) at each price grid point.

Styling: - Use a subtle color (e.g., light gray with alpha). - Dashed or dotted lines to distinguish from data. - Don't draw grid lines that are exactly on the axis (to avoid redundancy).

Combined example

Suppose: - time_range = [0, 86400000] (one day in ms) - chart_width = 800, chart_height = 300 - price_high = 105, price_low = 95 - target_grid_count = 5

X-axis (time): - time_span = 86400000 - ideal_interval = 86400000 / 5 = 17280000 ms (~4.8 hours) - Nice time interval: 4 hours = 14400000 ms (or 6 hours = 21600000 ms) - Grid times: 0:00, 4:00, 8:00, 12:00, 16:00, 20:00, 24:00 - Labels: "00:00", "04:00", "08:00", "12:00", "16:00", "20:00"

Y-axis (linear price): - price_span = 10 - ideal_interval = 10 / 5 = 2 - Nice interval: 2 (already nice) - Grid prices: 94, 96, 98, 100, 102, 104 (start at 94 to cover range) - Labels: "94.00", "96.00", "98.00", "100.00", "102.00", "104.00"

Log scale grid considerations

When use_log_scale = true:

  1. Y-axis intervals: Equal percentage changes produce equal pixel distances. Choose grid intervals based on percentage (e.g., 5%, 10%, 25%).
  2. Label format: Show actual prices, but the spacing is logarithmic.
  3. Optional intermediate grid: Draw lighter grid lines at 2× and 5× between powers of 10 for better readability.

Summary: key concepts for any 2D chart

Track: - Data range (x_min, x_max, y_min, y_max) - Chart size (width, height) - Scale type (linear or log for Y) - Config (grid count, spacing, formatting)

Derive: - Grid intervals: Use "nice numbers" or nice time intervals based on range and target count. - Grid positions: Generate grid values from intervals aligned to range, convert to pixels using the same transforms as data points. - Labels: Format grid values based on interval magnitude and scale type.

Draw: - Axis lines: Lines at chart edges. - Grid lines: Extend from axis through chart area. - Labels: Positioned at grid points, formatted for readability.

These concepts apply to any 2D chart: stock prices, scientific data, financial metrics, etc. The specific interval choices and label formats vary by domain, but the core algorithm remains the same.
